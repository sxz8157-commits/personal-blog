# n8n 自动化工作流实践讲义

## ——从监控到智能通知的完整自动化流程

------

### 一、课程目标

完成本课程后，学生将能够：

- 理解自动化工作流的基本逻辑与适用场景；
- 使用 RSS、Webhook、定时任务等不同触发方式；
- 调用大语言模型对原始信息进行摘要或翻译；
- 构建带条件判断与错误处理的健壮流程；
- 调试并优化工作流执行效果；
- 设计可扩展的自动化解决方案。

------

### 二、n8n 核心能力概述

n8n 不仅是一个“连接器”，更是一个**可编程的自动化引擎**。其核心能力包括：

1. **多类型触发器**：定时、Webhook、RSS、数据库变更、应用事件等；  
2. **数据处理节点**：JSON 解析、表达式计算、代码片段、AI 模型调用；  
3. **条件与分支**：根据数据内容决定后续路径；  
4. **动作执行**：发送邮件、推送消息、写入表格、调用 API；  
5. **错误处理与重试**：保障流程稳定性；  
6. **调试与日志**：查看每一步的输入输出，快速定位问题。

本课程将以一个真实需求贯穿始终，并逐步叠加上述能力。

------

### 三、基础案例：监控 CS2 新公告并邮件通知

#### 3.1 需求描述

当 Steam 发布《反恐精英2》（AppID 730）的新公告时，自动向指定邮箱发送通知。

#### 3.2 实现步骤（回顾）

- 使用 **RSS Read** 节点监听 `https://store.steampowered.com/feeds/news/app/730/`  
- 使用 **Email (SMTP)** 节点发送邮件  
- 激活工作流，实现定时轮询与去重

> 此为基础版本，仅实现“获取 → 发送”。

------

### 四、进阶一：引入 AI 节点——让通知更智能

原始公告通常为英文，且内容冗长。我们希望：

- 将标题和正文翻译为中文；
- 生成一段简洁摘要；
- 仅在公告涉及“更新”“修复”“赛事”等关键词时才通知。

#### 4.1 添加 AI 节点（以通义千问为例）

1. 在 RSS 节点与邮件节点之间插入 **“Qwen”** 节点（位于“AI”分类下）。  

2. 配置提示词（Prompt）：

   ```
   你是一名游戏资讯助手。请对以下 Steam 公告进行处理：
   
   原始标题：{{$json["title"]}}
   原文链接：{{$json["link"]}}
   
   任务：
   1. 将标题翻译成流畅的中文；
   2. 判断是否与游戏更新、平衡性调整、赛事或重大活动相关；
   3. 如果是，请输出 "relevant: true"，否则输出 "relevant: false"；
   4. 若相关，请用一句话概括公告核心内容。
   
   请严格按照以下 JSON 格式输出，不要包含其他文字：
   {
     "translated_title": "中文标题",
     "is_relevant": true,
     "summary": "一句话摘要"
   }
   ```

3. 保存节点。

> 注：需提前在 n8n 中配置 Qwen API Key（通过“认证”管理）。

#### 4.2 添加条件判断节点

1. 在 Qwen 节点后添加 **“IF”** 节点（位于“逻辑”分类）。  

2. 设置条件表达式：

   ```
   {{$json["is_relevant"]}} == true
   ```

3. 连接“真”分支到邮件节点，“假”分支可留空或记录日志。

#### 4.3 修改邮件内容

邮件主题与正文引用 AI 输出：

- 主题：`【CS2 更新】{{$json["translated_title"]}}`

- 正文：

  ```
  {{$json["summary"]}}
  
  原文链接：{{$json["link"]}}
  ```

效果：只有真正重要的公告才会触发邮件，且内容为中文摘要。

### 五、进阶二：添加 Webhook ——支持手动触发与外部集成

虽然 RSS 可自动监控，但有时需要**立即检查**或**从其他系统触发**。

#### 5.1 添加 Webhook 触发入口

1. 在工作流起始处添加 **“Webhook”** 节点（与 RSS 节点并列）。  

2. 配置方法为 POST，保存后获得 URL，例如：

   ```
   https://your-id.n8n.cloud/webhook/cs2-check
   ```

#### 5.2 合并数据源

使用 **“Merge”** 节点或 **“Set”** 节点统一数据结构，使后续流程无需区分来源。

> 更简单做法：将 RSS 和 Webhook 都连接到同一个“获取公告详情”子流程（可通过子工作流实现，本课程暂用线性流程）。

#### 5.3 应用场景

- 在手机浏览器中收藏该 Webhook 链接，点击即可手动触发检查；
- 未来可从 Discord、飞书机器人等调用此接口，实现跨平台触发。

### 六、进阶三：错误处理与调试技巧

#### 6.1 常见问题

- RSS 源暂时不可用；
- 邮箱 SMTP 认证失败；
- AI 接口返回格式错误。

#### 6.2 添加错误处理

1. 点击任意节点右上角的“⚙️”图标，启用“错误处理”。  
2. 添加 **“Error Trigger”** 节点，连接至邮件或日志节点。  
3. 在错误节点中发送告警邮件，内容包含：
   - 错误时间
   - 失败节点名称
   - 错误信息（`{{$json["message"]}}`）

#### 6.3 调试方法

- 点击任一节点，查看“上次执行”的输入/输出数据；
- 使用 **“Debug”** 节点临时打印中间结果；
- 在表达式中使用 `$now`、`$executionId` 等变量辅助追踪。

------

### 七、工作流结构总结

最终工作流包含以下模块：

```
[ RSS 定时检查 ] ──┐
                   ├─→ [ 获取公告数据 ] → [ 调用 AI 处理 ] → [ 条件判断 ] → [ 发送邮件 ]
[ Webhook 手动触发 ] ──┘
                              ↓
                      [ 错误处理分支 ]
```

该结构具备：

- **双触发机制**（自动 + 手动）  
- **智能过滤**（AI 判断相关性）  
- **用户友好输出**（中文摘要）  
- **运行可靠性**（错误告警）

### 八、扩展思考与应用场景

1. **多游戏监控**：复制流程，修改 AppID 即可监控 Dota2（570）、PUBG（578080）等。  
2. **多通道通知**：除邮件外，增加钉钉、企业微信、Telegram 通知。  
3. **数据存档**：将公告存入 Notion 或腾讯文档，构建游戏资讯库。  
4. **社区联动**：当检测到赛事公告时，自动在 Discord 发帖提醒战队报名。
