# 个人博客质感与轻组件优化方案

> 调研日期：2026-10-29。主对照项目均超过 5,000 GitHub Star，数字为当日 API 快照。本文是待实施方案，本轮只调研、核对与编写文档，不改变网站页面或功能。

## 1. 建议先做什么

保留二次元壁纸、紫粉色点缀、透明玻璃、首页无卡片，以及“首屏词云 → 下方搜索列表”。把精力集中在三件事：**让文字和背景各有层次，让各页像同一套设计，让小组件帮助阅读。**

第一轮建议交付：统一文字与玻璃材质、缩短重复过渡、阅读进度与目录高亮、代码复制。第二轮再增加继续阅读、稍后读、静读开关。精选内容与订阅入口放在内容数据补齐之后。

视觉方向可概括为“安静的玻璃阅读空间”：壁纸负责个性，文字负责秩序，紫色负责标记操作。保留现有字体与整体构图，不引入远程字体、整套新 UI 框架或全站换主题。

## 4. 当前最影响质感的五个具体问题

### 4.1 文章页已有新规范，其他页仍各用一套

文章页已经使用 `#242035` 主文字、`#5d566d` 次文字和 `#7c3aed` 操作色；全局变量仍保留白色主文字，部分页面又硬编码黑色。`.glass-card` 在全局样式和 `App.vue` 中分别定义。不同容器组合后，文字、阴影和玻璃浓度容易不一致。

**建议：以新文章页为基准提炼公共变量，再逐页接入。** 先确定文字、边框、两级玻璃和阴影，不直接批量替换全站颜色。保持现有字体，不增加字体下载。

依据：[主题变量](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/styles/variables.scss)、[全局卡片](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/styles/main.scss)、[当前文章页](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/views/Articles.vue)。

### 4.2 背景很有个性，阅读层次还可以更稳定

本次首页与阅读页截图中，人物脸部和高饱和色块会出现在文字后方；关于页又有外层和内层玻璃叠加。单纯继续增加模糊，会改变材质并增加合成负担。

**建议：保留背景清晰区域，在文字所在局部使用很轻的柔光渐变，正文卡片使用相对稳定的一层玻璃。** 默认不把整站漂白，不增加首页大卡片。亮图、暗图、黑白线稿和视频分别对照，不能只验收最顺眼的一张图。

### 4.3 标题与容器尺寸缺少一致节奏

桌面实测：文章页主标题 42px，关于/更多页为 48px；全局内页窗口使用 54% 宽度，文章页则已使用最大 1040px 的响应式容器。中等屏幕上，同级页面容易显得一页松、一页挤。

**建议：同级内页主标题收敛到 36–42px，手机 28px；版心统一使用有上限的响应式宽度。** 正文目前最大 760px 和较宽松行高已经合理，保留；主要统一标题间距、按钮、说明文字和边界对齐。

### 4.4 动画层层叠加，容易把“舒缓”变成“拖沓”

路由为先退后进，退出/进入各 450ms；关于/更多另有淡入和延迟；首页标题反复输入、删除。存在多处 `transition: all` 与常驻 `will-change`。

**建议值（待前后对照验证）：** 退出约 120ms、进入约 200ms；按钮反馈 120–180ms；只有可操作元素有轻微移动，阅读面板不放大。打字效果保留首次进入的一次，之后稳定停留，或至少显著延长完整标题停留。减少动态效果偏好时关闭非必要运动。

依据：[App.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/App.vue)、[Home.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/views/Home.vue)。

### 4.5 长文工具没有完全围绕真正滚动的容器

MYSQL 桌面正文滚动高度约 59,667px，可视高度 894px；手机约 65,279px/702px。正文在卡片内部滚动。现有大纲可以定位，但 Markdown 大纲链接没有滚动跟随高亮；全局返回顶部按钮监听的是 `window.scrollY`。

**建议：进度、当前章节、继续阅读和返回顶部共用正文容器。** 保留固定阅读区，不把正文改回整页滚动；也不要另加一个实际上不随正文变化的全局进度条。

依据：[ArticleDetail.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/views/ArticleDetail.vue)、[BackToTop.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/components/BackToTop.vue)。

## 5. 小组件清单：优先增加这几种

**摆放规则：新增常驻工具每个视口最多两组；同一功能不重复出现。桌面复用左侧大纲区，手机折叠到标题旁或短工具条，不新增第三列。**

| 组件 | 放在哪里、长什么样 | 行为与数据来源 | 优先级 |
| --- | --- | --- | --- |
| 阅读进度 + 当前章节 | 大纲标题旁一行小字与细进度线；手机标题下 2px 进度线 | Markdown 监听正文容器，大纲高亮跟随；短文隐藏进度。PDF 用当前页/总页数，XLSX 显示工作表，不套像素阅读百分比 | **P0** |
| 代码复制 | 代码块右上角一个小按钮；电脑 hover/键盘聚焦可见，手机直接可见 | 复制当前代码块，原地显示“已复制”；失败提供明确反馈，不弹全屏提示。原生 Clipboard API 即可 | **P0** |
| 继续阅读 | 文章列表标题上方一条很薄的记录，仅在有本地记录时出现 | 本机保存最近阅读的文章与位置；点击才恢复，页面不偷偷跳动。清除浏览器数据会丢失，不宣称跨设备同步 | **P1** |
| 稍后读 | 每篇列表项末端一个轻量书签按钮，列表工具区有“稍后读”筛选 | 使用本地存储，空集合不占额外板块；按钮与文章链接保持独立交互区域 | **P1** |
| 静读开关 | 标题工具区一个“静读”按钮，和现有工具合成一组 | 用户主动开启后暂停动态壁纸、让阅读区背景更平稳；退出后恢复原设置。保留透明感，不遮成纯白纸 | **P1** |
| 精选 3 篇 / 正在做什么 | 精选放在文章列表附近；近况放关于或更多页的一行内容 | 真实内容手动维护；无资料时隐藏。首页如展示近况，仅作轻量文字，不增加卡片 | **P2** |
| 订阅入口 | 更多页或页脚的小文字链接 | 先让 RSS 覆盖当前公开文档，再展示“订阅更新”。目前空 feed 不适合当成已可用的全站订阅 | **P2** |

### 5.1 阅读工具的实现细节

1. Markdown 进度从 `scrollTop / (scrollHeight - clientHeight)` 计算；分母为零时隐藏。`scroll` 监听使用被动模式，用一个 `requestAnimationFrame` 合并更新。
2. 大纲监听以 `articleScrollEl` 为根容器；图片加载、容器变化后重新校准。切换文章清理监听，标签隐藏时停止无用更新。
3. 保存阅读位置优先使用章节锚点和相对位置；正文变化导致锚点不存在时提示从头阅读。无需把阅读记录写回服务器。
4. “回到顶部”对阅读页滚正文容器，对列表页滚窗口；复用现有按钮的外观和路由判断。
5. 代码按钮由受控 Vue 组件或工具层创建。**保留正文净化，不为了显示按钮而放开不可信文档的 `<button>`。** 当前 `safeHtml.js` 明确禁止该标签。

### 5.2 内容组件先过数据这一关

- 当前 24 项均为文档，且缺少有效日期，因此先做“精选”，不要按旧文件时间生成“最近更新”或归档年份；也不要用发布日期补齐缺失数据。
- 现有数据库文章索引只有 ID、标题、浏览/点赞等字段，不含完整摘要、时间或封面。需要时为公开索引补充可选字段；继续沿用旧字段，保证兼容。
- 已有数据库文章关联接口只按数据库文章分类工作，不能直接拿来推荐文件文档。精选和主题分组可先用小份受审配置，后续再接管理后台。
- 后台页面文案有字段白名单。近况若接后台，应扩展现有 `page_defaults.py`/文案配置与 API 说明，不能随意塞入一个后端会忽略的字段。
- 阅读时间只能在拿到正文后估算，并标“预计”；PDF、XLSX 等格式不猜字数。不能为显示阅读时间而在首屏批量下载 24 份正文。

## 6. 各页的具体排布

### 首页：保持空灵，让介绍稳定

保留现有头像壁纸、居中欢迎语和两个主入口。改善文字局部底色与按钮对齐，减少反复删除标题；首轮不添加侧栏、统计大屏或新卡片。用户将来有真实近况时，可在原文案附近增加一行低存在感文字。

### 文章页：沿用现有入口和搜索成果

```text
┌──────────────── 原旋转词云 ────────────────┐
│                标题与简短说明              │
│                词云 / 向下提示             │
└───────────────────────────────────────────┘
┌─────────────── 文章与笔记 ─────────────────┐
│  [有记录时：继续阅读 ……]                    │
│  搜索框                       [稍后读]       │
│  全部 / MD / PDF / …                       │
│  标题 · 真实摘要                   [书签]    │
│  标题 · 真实摘要                   [书签]    │
│  分页                                     │
└───────────────────────────────────────────┘
```

这里的草图仅表达位置关系。背景、玻璃、色彩与字体沿用当前页面；“稍后读”是本地收藏，和文档格式筛选是两个维度。

### 阅读页：在现有两栏中补齐工具

```text
桌面： [返回 / 标题]       [正文顶端：静读]
      [大纲 · 进度]       [正文 / 代码右上角复制]
      [当前章节高亮]      [文末少量相关内容]

手机： [返回] 标题 [大纲]
      ──细进度线──
      [固定正文阅读区]
      [收起的阅读工具；不压住正文]
```

### 关于与更多页：先统一质感，再精简信息

采用与文章页一致的标题、文字色和玻璃浓度；减少外层/内层卡片重复模糊与阴影。现有技能、经历、项目和开发日志继续保留。近况使用真实的短内容；订阅入口等 RSS 补齐后再打开。

| --- | --- |
| 字体 | 沿用当前中文系统字体栈；统一实际生效的字体入口，不新增远程字体 |
| 文字颜色 | 以文章页 `#242035 / #5d566d / #7c3aed` 为基础，明确主文字、说明与操作三个角色 |
| 字号 | 桌面内页主标题 36–42px、章节标题 22–28px、正文 16–17px；手机主标题 28px，辅助文字优先保持 12–14px 可读 |
| 间距 | 采用 8/12/16/24/32/48px 的有限梯度；同级标题和按钮对齐 |
| 材质 | 外层玻璃与内部轻分隔两级；避免每个小部件都加模糊、边框、阴影和渐变 |
| 圆角 | 主要面板沿用约 20–24px，小控件约 8–12px；保留现有识别感 |
| 动态 | 非必要循环减少；反馈限定颜色/透明度/微移，正文面板不缩放；减少动态效果偏好可用 |
| 小图标 | 优先复用已有图标或少量 SVG；线宽与尺寸统一，不下载整套新图标包 |

背景与文字对比度必须按实际图片检测，不能把某个透明度值当成已经达标。手机键盘打开、横屏、长标题和极长代码行要单独验收。

## 8. 分批实施与验收

### 第一批：整理视觉与阅读基本功

范围：公共颜色/材质变量，关于/更多页接入统一规则，控制动画，阅读进度/当前章节、代码复制。保留词云、首页无卡片和固定阅读方式。

交付标准：同级页面标题、边距和说明文字一致；阅读进度跟随真正的正文；代码可用鼠标、键盘和手机复制；不存在正文放大或工具覆盖返回入口。

### 第二批：让访问有连续性

范围：继续阅读、稍后读、静读开关；必要时补公开索引的可选元数据。

交付标准：没有记录时不出现空板块；记录能删除，存储不可用时基本阅读不受影响；文档改动后不会恢复到错误章节；默认不自动跳动、不跨设备承诺。

### 第三批：内容与订阅

范围：真实精选、近况、主题关联、有效日期和 RSS 覆盖。

交付标准：每条内容有真实来源，缺日期就隐藏；草稿不会进入索引/推荐/订阅；当前文件文档出现在实际 RSS 条目中，不能只验收 HTTP 200。

### 每批共同检查

- 1440/768/390/320px，无横向溢出；亮、暗、密集线稿、动态背景均能读。
- 保留音乐、站内 PDF、文章搜索、格式筛选、分页、隐藏三连击入口。
- 不增加首屏外部请求；新组件按当前路由加载，不为阅读小功能批量获取正文。
- 首批新增组件脚本的设计预算：首屏 gzip 增量尽量 ≤8KB；这是待测预算，不是已测体积。无必要不增加运行依赖。
- 为真实用户体验设置目标：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，并按移动/桌面分别看第 75 百分位。这些是 [Web Vitals 官方目标](https://web.dev/articles/vitals)，本轮没有测得或宣称达到。
- 按既定流程执行：修改 → 受影响验证 → 中文 Git 提交/推送 → 服务器备份与同步 → 线上真实验收。静态主题作者的跑分不能替代咱们自己的内容和网络测试。

## 9. 本轮暂缓的组件

| 组件 | 暂缓理由 |
| --- | --- |
| 大型天气、时钟、实时统计面板 | 与文章阅读关系较弱，会增加视觉区块和数据维护 |
| 鼠标彩带、粒子、看板娘、满屏动效 | 当前背景已经足够鲜明，继续叠加会增加运动和注意力竞争 |
| 首屏 GitHub 贡献热力图或自动拉取社交动态 | 需要额外数据请求和缓存，先把本地内容与阅读体验做好 |
| 第二套音乐播放器、第二个目录或悬浮工具盘 | 当前已经有对应入口，增加重复操作 |
| 缺日期时强行展示更新榜、把空 RSS 包装成全站订阅 | 当前数据不支持这个展示结果 |
