# 个人博客质感与轻组件优化方案

> 调研日期：2026-10-29。主对照项目均超过 5,000 GitHub Star，数字为当日 API 快照。本文是待实施方案，本轮只调研、核对与编写文档，不改变网站页面或功能。

## 1. 建议先做什么

保留二次元壁纸、紫粉色点缀、透明玻璃、首页无卡片，以及“首屏词云 → 下方搜索列表”。把精力集中在三件事：**让文字和背景各有层次，让各页像同一套设计，让少量小元素可以点击和拖动。**

用户最新明确的小组件方向是“页面上可互动的小元素，可点可拖”。原先的继续阅读、稍后读、静读开关已从实施建议中移除。第一轮先统一视觉，再给可拖动小唱片和弹性小挂件做预览；换背景控件与互动磁贴作为后续候选。阅读进度、目录高亮和代码复制归入独立的阅读体验完善，不用它们代替用户要的互动小元素。

视觉方向可概括为“安静的玻璃阅读空间”：壁纸负责个性，文字负责秩序，紫色负责标记操作。保留现有字体与整体构图，不引入远程字体、整套新 UI 框架或全站换主题。

## 4. 当前最影响质感的五个具体问题

### 4.1 文章页已有新规范，其他页仍各用一套

文章页已经使用 `#242035` 主文字、`#5d566d` 次文字和 `#7c3aed` 操作色；全局变量仍保留白色主文字，部分页面又硬编码黑色。`.glass-card` 在全局样式和 `App.vue` 中分别定义。不同容器组合后，文字、阴影和玻璃浓度容易不一致。

**建议：以新文章页为基准提炼公共变量，再逐页接入。** 先确定文字、边框、两级玻璃和阴影，不直接批量替换全站颜色。保持现有字体，不增加字体下载。

依据：[主题变量](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/styles/variables.scss)、[全局卡片](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/styles/main.scss)、[当前文章页](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/views/Articles.vue)。

### 4.2 背景很有个性，阅读层次还可以更稳定

本次首页与阅读页截图中，人物脸部和高饱和色块会出现在文字后方；关于页又有外层和内层玻璃叠加。单纯继续增加模糊，会改变材质并增加合成负担。

**建议：保留背景清晰区域，在文字所在局部使用很轻的柔光渐变，正文卡片使用相对稳定的一层玻璃。** 默认不把整站漂白，不增加首页大卡片。亮图、暗图、黑白线稿和视频分别对照，不能只验收最顺眼的一张图。

### 4.3 标题与容器尺寸缺少一致节奏

桌面实测：文章页主标题 42px，关于/更多页为 48px；全局内页窗口使用 54% 宽度，文章页则已使用最大 1040px 的响应式容器。中等屏幕上，同级页面容易显得一页松、一页挤。

**建议：同级内页主标题收敛到 36–42px，手机 28px；版心统一使用有上限的响应式宽度。** 正文目前最大 760px 和较宽松行高已经合理，保留；主要统一标题间距、按钮、说明文字和边界对齐。

### 4.4 动画层层叠加，容易把“舒缓”变成“拖沓”

路由为先退后进，退出/进入各 450ms；关于/更多另有淡入和延迟；首页标题反复输入、删除。存在多处 `transition: all` 与常驻 `will-change`。

**建议值（待前后对照验证）：** 退出约 120ms、进入约 200ms；按钮反馈 120–180ms；只有可操作元素有轻微移动，阅读面板不放大。打字效果保留首次进入的一次，之后稳定停留，或至少显著延长完整标题停留。减少动态效果偏好时关闭非必要运动。

依据：[App.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/App.vue)、[Home.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/views/Home.vue)。

### 4.5 长文工具没有完全围绕真正滚动的容器

MYSQL 桌面正文滚动高度约 59,667px，可视高度 894px；手机约 65,279px/702px。正文在卡片内部滚动。现有大纲可以定位，但 Markdown 大纲链接没有滚动跟随高亮；全局返回顶部按钮监听的是 `window.scrollY`。

**建议：进度、当前章节和返回顶部共用正文容器。** 保留固定阅读区，不把正文改回整页滚动；也不要另加一个实际上不随正文变化的全局进度条。

依据：[ArticleDetail.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/views/ArticleDetail.vue)、[BackToTop.vue](https://github.com/sxz8157-commits/personal-blog/blob/e6e5081031f5f4ee490c3acdd1b86b118748eec6/src/components/BackToTop.vue)。

## 5. 可点可拖的页面互动元素

**用户定义优先：这一节的小组件是可玩、可点击、可拖动的小元素。** 以下是待选方案，不表示已经决定全部加入，更不表示已经实现。互动创意为针对本博客的设计提案；前述高 Star 项目提供排版和组件组织参考，不宣称它们都包含这些小玩意。

### 5.1 互动候选与建议顺序

| 元素 | 点击怎么玩 | 拖动怎么玩 | 位置与风格 | 顺序 |
| --- | --- | --- | --- | --- |
| **小唱片** | 点击播放/暂停现有音乐；唱片随真实播放状态慢转，暂停就停 | 拖动到喜欢的位置，松手轻轻贴边；提供复位 | 桌面约 48–56px，手机触控区至少 44px；只呈现一枚简洁唱片，沿用紫色点缀，不额外弹一大张卡片 | **第一轮候选** |
| **小纸飞机或弹性挂件** | 点击轻弹一下、短暂改变姿态或显示一句真实短句 | 拉动后松手轻回弹，可在限定小区域摆放 | 优先放更多页底部/留白处；静止时安静，不满屏飞，不自动发声。纸飞机和挂件造型先选一种做预览 | **第一轮候选** |
| 手动换壁纸小控件 | 点击切到下一张图片/下一段视频，准备好才切换 | 拖动改变控件停靠位置，不能靠拖动整张背景抢滚动手势 | 复用原壁纸队列和失败保留机制，不另建背景播放器 | 第二轮候选 |
| 灵感磁贴 | 点击翻开一条简短介绍或小句子，点击空白收起 | 在更多页的限定区域内拖动几枚标签，松手轻轻吸附 | 只用 2–3 枚小元素；文字由真实内容提供，不给首页增加大卡片或信息面板 | 第二轮候选 |

建议先评估“小唱片 + 一处页面内的小挂件”，通过预览再决定是否补其他元素。最多一个新增全局可拖元素；其余互动留在页面自己的区域里。用户没有选定的造型、短句和数量不当作既定需求。

### 5.2 让互动有趣但不吵

1. 明确区分点击和拖动，建议移动超过约 6–8px 才进入拖动；拖完不能误触播放、跳页或切壁纸。
2. 拖动跟随手指，松手只做一次短回弹或贴边；没有操作时不乱跑、不循环蹦跳，不追加鼠标彩带、全屏粒子和提示音。
3. 保持原壁纸和紫粉玻璃风格，小元素用清楚的轮廓与低强度阴影；不出现新的大型浮窗、仪表盘或第三列侧栏。
4. 小唱片复用 `Navbar.vue` 的同一个音频元素与播放状态，不同时播放第二路音频；点击才触发播放，打开页面不自动出声。
5. 手动换背景与现有定时轮播共用切换入口，避免并发切换、重复下载或闪黑；失败继续保留当前背景。
6. 提供容易发现的“复位/收起”。保存位置只作用于该互动元素，不记录文章阅读行为；窗口变化后重新限制在可见范围内。
7. 减少动态效果偏好下仍能点击和拖动，省略弹簧动画，直接落位；键盘可聚焦，提供等效的点击、移动或复位入口。

### 5.3 移动端的互动边界

- 手机只保留一个全局小元素，其他互动放更多页的指定区域；不把所有悬浮元素同时摆出来。
- 给拖动提供明确的触控区域，触控区建议至少 44×44px。按住这个区域才接管拖动，在正文和词云附近滑动仍正常滚动。
- 元素不得遮挡导航、返回、大纲、分页、复制和系统安全区；位置按视口重新约束，转屏后不能跑到屏幕外。
- 软键盘或音乐盒展开时，互动元素自动收起或避让；不在最上层盖住输入框、关闭按钮和结果。
- 避免只能依靠 hover 才发现的操作；手机轻点有明确但短暂的反馈，拖动后不会触发链接或影响系统返回。

### 5.4 阅读体验与内容数据另行完善

阅读进度、目录高亮、代码复制继续作为基础体验候选，不计入这次互动组件数量。进度与目录监听正文内部滚动；PDF 用页数，XLSX 用工作表。代码按钮由受控 Vue 工具层创建，保持正文净化白名单，不放开不可信文档的按钮标签。

当前 24 项内容是缺少有效日期的文件文档，因此精选、最近更新、主题关联和 RSS 仍需先核对数据。后台文案有字段白名单，磁贴短句若接入后台，应扩展现有页面文案配置，不能随便塞入会被忽略的字段。不会为这些互动元素增加天气 API、访问统计或新的数据库表。

## 6. 各页的具体排布

### 首页：保持空灵，让介绍稳定

保留现有头像壁纸、居中欢迎语和两个主入口。改善文字局部底色与按钮对齐，减少反复删除标题；不添加首页侧栏、统计大屏或新卡片。小唱片若全局展示，只在边缘占一个小位置，不遮标题和主按钮。

### 文章页：沿用现有入口和搜索成果

```text
┌──────────────── 原旋转词云 ────────────────┐
│                标题与简短说明              │
│                词云 / 向下提示             │
└───────────────────────────────────────────┘
┌─────────────── 文章与笔记 ─────────────────┐
│  搜索框                                   │
│  全部 / MD / PDF / …                       │
│  标题 · 真实摘要                   [阅读]    │
│  标题 · 真实摘要                   [阅读]    │
│  分页                                     │
└───────────────────────────────────────────┘
```

这里的草图仅表达位置关系。背景、玻璃、色彩与字体沿用当前页面；文章列表保持简洁。若小唱片常驻，应停靠在不会遮住列表操作的边缘。

### 阅读页：在现有两栏中补齐工具

```text

      ──细进度线──
```

### 关于与更多页：先统一质感，再精简信息

采用与文章页一致的标题、文字色和玻璃浓度；减少外层/内层卡片重复模糊与阴影。现有技能、经历、项目和开发日志继续保留。可在更多页底部或留白区试放一处小纸飞机/挂件，后续再考虑限定区域的互动磁贴；订阅入口等 RSS 补齐后再打开。

## 7. 移动端专项适配

移动端与桌面保持同一视觉风格，但按手机的阅读顺序、触控操作和可用高度重新组织。下面是待实施/待验收要求，**本轮只对 390px 做了当前页面采样，不将其他设备写成已通过。**

### 7.1 按实际内容宽度分层

| 宽度/场景 | 布局建议 | 需要重点验收 |
| --- | --- | --- |
| 320–359px 窄手机 | 单列，页面边距约 12px；辅助操作收起，格式筛选可换行 | 长文件名、分页、返回/大纲按钮不挤压正文；无横向溢出 |
| 360–430px 常见手机 | 单列，边距约 16px；保留现有紧凑导航和音乐按钮 | 390px 为主要对照，同时检查 360/430px；操作目标建议至少 44×44px |
| 431–767px 大手机/横屏 | 仍以一列阅读为主，限制内容最大宽度 | 低屏高时词云、菜单和播放器不能占满可用空间 |
| 768–1023px 平板 | 优先舒适的正文宽度；大纲根据可用宽度折叠 | 不沿用固定 54% 版心，不因断点突然挤成窄列 |
| ≥1024px 桌面 | 原有两栏阅读与更完整的辅助信息 | 与手机共享颜色、间距和组件规则，避免形成另一套主题 |

这些区间是本项目的设计建议，最终断点应由内容是否拥挤决定，不能只按设备名称判断。

### 7.2 各页在手机上的处理

| 页面 | 适配方向 | 必须保留的体验 |
| --- | --- | --- |
| 首页 | 主标题约 28–32px，预留稳定高度；两个主入口保持清晰。壁纸可为手机设置单独焦点位置，避免把主体裁掉或正好挡住文字 | 无首页卡片、无桌面侧栏；保留人物壁纸和原有主入口 |
| 词云开场 | 保留词云并提供明确的向下提示。窄屏长标签可采用可理解的短显示名，详情仍使用完整文件 ID；低屏高时按可用高度减小空白 | 不替换成纯列表；不再次扩大字号制造重叠，不影响纵向滚动和点选 |
| 搜索与文章列表 | 搜索框整行，输入字号建议 16px；格式筛选允许自然换行，互动元素避让搜索框；标题最多两行，摘要保持可读长度 | 中文输入法组合输入不被打断；搜索不跳页、不刷新整站，清空入口可触达 |
| 固定阅读区 | 延续顶部返回/标题/大纲和下方内部滚动正文；细进度线与工具贴合阅读区，正文约 16–17px | PDF 站内翻页、长代码横向滚动、长文纵向滚动互不抢手势，不改为下载/外跳 |
| 大纲与阅读工具 | 大纲收在现有按钮后，新增工具合并成短工具条或一个可展开入口 | 展开可关闭，焦点与触控可返回，关闭后阅读位置保留；不新增常驻第三列 |
| 关于与更多 | 单列，统一头像、标题、段落与技能间距；精选/近况以少量内容展示 | 不把桌面多栏缩成密集小格，不挤出横向滚动 |
| 音乐盒 | 继续使用现有手机播放器；打开时避让新的阅读操作，关闭控制始终可见 | 声音不因切页中断，手机浏览器拒绝自动播放时仍有正常手动入口 |

### 7.3 触控、软键盘和安全区

- **触控反馈独立于 hover。** 唱片控制、复制和关闭在触屏可见；不要让用户先悬停才能发现入口。按钮与整行文章链接不能形成互相嵌套的点击区。
- **词云不阻断页面滚动。** 区分点击和拖动；不在整页拦截 `touchmove`，不抢系统侧滑返回。短显示名只改变展示，完整文件名仍用于详情路由与搜索。
- **键盘弹出后仍能操作。** 搜索框、清空和结果提示应可见，输入不因滚动或视口变化丢失；工具不固定压在键盘上。收起键盘后恢复合理的阅读区高度。
- **沿用动态视口处理。** 现有阅读页已经有 `100dvh` 与回退样式；新增组件继续按动态工具栏、横屏和安全区验收，不能只在桌面模拟器里用固定 844px 高度。
- **安全区与播放器共同避让。** 底部操作考虑 `safe-area-inset-bottom`，顶部考虑刘海与浏览器布局；先核对是否采用覆盖式视口，再决定是否调整 viewport 配置。避免阅读工具、音乐盒、返回顶部三组浮层叠在同一角落。
- **减少手机额外下载。** 壁纸使用合适尺寸与焦点；慢网/省流偏好可提供静图策略。未播放音乐不预取整批音频，新增组件不增加外部天气、热力图等首屏请求。

### 7.4 移动端验收清单

1. 320/360/390/430px 竖屏，常见横屏，以及 768px 平板；分别检查长标题、多关键词、空结果和较大的系统字号。
2. iOS Safari、Android Chrome，再补微信内置浏览器；**这些实体设备验证尚未执行**，后续交付必须单独记录实际设备与版本。
3. 搜索框聚焦 → 键盘打开 → 输入中文 → 清空 → 点击文章 → 返回，状态和布局正常；不会被播放器或工具条挡住。
4. 手指滑过词云可以继续下滚，轻点可准确打开；旋转屏幕后画布尺寸与命中坐标一致。
5. Markdown 长代码、图片、表格，以及 PDF 翻页分别验收；横向代码滚动不导致整个页面左右漂移。
6. 大纲展开/关闭、复制反馈、音乐控制和系统返回正常；拖动唱片/挂件不会误触点击，复位可用，打开键盘或音乐盒时不会遮挡操作。
7. 明暗壁纸、低屏高、刘海/底部手势区、减少动态效果偏好和弱网均覆盖。桌面同页同步回归，确认自适应改动没有破坏原布局。

## 8. 视觉规格建议

以下为设计起点，最终以实际明暗背景截图对照为准。

| 项目 | 建议约束 |
| --- | --- |
| 字体 | 沿用当前中文系统字体栈；统一实际生效的字体入口，不新增远程字体 |
| 文字颜色 | 以文章页 `#242035 / #5d566d / #7c3aed` 为基础，明确主文字、说明与操作三个角色 |
| 字号 | 桌面内页主标题 36–42px、章节标题 22–28px、正文 16–17px；手机主标题 28px，辅助文字优先保持 12–14px 可读 |
| 间距 | 采用 8/12/16/24/32/48px 的有限梯度；同级标题和按钮对齐 |
| 材质 | 外层玻璃与内部轻分隔两级；避免每个小部件都加模糊、边框、阴影和渐变 |
| 圆角 | 主要面板沿用约 20–24px，小控件约 8–12px；保留现有识别感 |
| 动态 | 非必要循环减少；反馈限定颜色/透明度/微移，正文面板不缩放；减少动态效果偏好可用 |
| 小图标 | 优先复用已有图标或少量 SVG；线宽与尺寸统一，不下载整套新图标包 |

背景与文字对比度必须按实际图片检测，不能把某个透明度值当成已经达标。手机键盘打开、横屏、长标题和极长代码行要单独验收。

## 9. 分批实施与验收

### 第一批：统一质感，验证两种互动

范围：统一公共颜色/材质、控制重复动画；为“小唱片 + 更多页小挂件”做可点可拖的预览。继续保留词云、首页无卡片和固定阅读方式。

交付标准：点击、拖动、释放和复位行为明确；唱片使用原音乐播放状态；挂件只在指定区域活动；电脑和手机都不遮操作。先根据预览确认造型，再决定正式保留哪些元素。

### 第二批：按实际效果补充互动

范围：第一批体验合适后，再考虑手动换壁纸控件或 2–3 枚互动磁贴，不一次全部叠加。阅读进度、大纲高亮、代码复制作为独立的基础体验任务处理。

交付标准：同一视口最多一个新增全局互动元素；手机滚动、键盘、音乐盒和转屏兼容；没有多路音频、并发壁纸切换、自动声音或重复下载。

### 第三批：内容与订阅

范围：真实精选、近况、主题关联、有效日期和 RSS 覆盖。

交付标准：每条内容有真实来源，缺日期就隐藏；草稿不会进入索引/推荐/订阅；当前文件文档出现在实际 RSS 条目中，不能只验收 HTTP 200。

### 每批共同检查

- 1440/768/390/320px，无横向溢出；亮、暗、密集线稿、动态背景均能读。
- 保留音乐、站内 PDF、文章搜索、格式筛选、分页、隐藏三连击入口。
- 不增加首屏外部请求；新组件按当前路由加载，不为阅读小功能批量获取正文。
- 首批新增组件脚本的设计预算：首屏 gzip 增量尽量 ≤8KB；这是待测预算，不是已测体积。无必要不增加运行依赖。
- 为真实用户体验设置目标：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，并按移动/桌面分别看第 75 百分位。这些是 [Web Vitals 官方目标](https://web.dev/articles/vitals)，本轮没有测得或宣称达到。
- 按既定流程执行：修改 → 受影响验证 → 中文 Git 提交/推送 → 服务器备份与同步 → 线上真实验收。静态主题作者的跑分不能替代咱们自己的内容和网络测试。

## 10. 本轮暂缓的组件

| 组件 | 暂缓理由 |
| --- | --- |
| 大型天气、时钟、实时统计面板 | 与文章阅读关系较弱，会增加视觉区块和数据维护 |
| 鼠标彩带、粒子、看板娘、满屏动效 | 当前背景已经足够鲜明，继续叠加会增加运动和注意力竞争 |
| 首屏 GitHub 贡献热力图或自动拉取社交动态 | 需要额外数据请求和缓存，先把本地内容与阅读体验做好 |
| 第二套音频播放器、第二个目录或大型悬浮工具盘 | 小唱片应控制现有音乐，其他操作复用已有入口 |
| 缺日期时强行展示更新榜、把空 RSS 包装成全站订阅 | 当前数据不支持这个展示结果 |
